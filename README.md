# 校招 JD 抓取 + 筛选工具

> 秋招岗位分散、海量、人工筛选低效 —— 用 Claude Code 协作开发的抓取 + 筛选工具，把数小时的 JD 人工筛选压缩到 10 分钟。

---

## 解决的痛点

2027 届秋招，光一个大厂就有几百个校招岗位，叠加牛客、Boss、各家官网，JD 总量上千。人工逐条阅读、判断「这个岗适不适合我」，需要数小时，还容易漏掉高匹配岗位、误投低匹配岗位。

这个工具把「抓取 → 筛选 → 评分」三步自动化。

---

## 核心方案

### 1. 抓取 —— 适配器模式 + TLS 指纹伪装

```
adapters/
├── base.py         # BaseAdapter 抽象基类 + JobPost 统一数据模型
├── bytedance.py    # 字节适配器（curl_cffi 伪造 TLS 指纹绕过反爬）
└── __init__.py     # 适配器注册表
```

- **适配器模式**：每家公司 API 结构、反爬策略不同，各自实现 `fetch()`、注册进 `ADAPTERS` 即可扩展，不破坏已有代码
- **TLS 指纹伪装**：`curl_cffi` 的 `impersonate="chrome131"` 把请求伪装成真实 Chrome，绕过官网的 TLS 反爬检测

### 2. 筛选 —— 5 维匹配度评分

不满足于「关键词黑白名单」的粗暴过滤，把每个 JD 拆成 5 个维度打分，让匹配度**可解释、可排序**：

| 维度 | 满分 | 说明 |
|------|------|------|
| 方向命中 | 5 | Agent / RAG / MCP / 大模型应用 等核心方向词命中数 |
| 工程信号 | 3 | 偏工程落地（含「不涉及训练」「工程化」等） |
| 专业弹性 | 2 | 「等相关专业」=2（非科班有机会）；「计算机相关专业」=0（硬卡） |
| 技能命中 | 10 | 个人技术栈命中（Claude Code / LangGraph / MCP...，权重=熟练度） |
| 城市匹配 | 2 | 北京优先 |

**一票否决**：模型研究/训练（预训练 / SFT / RLHF）、学历硬门槛（硕士+）、非应用方向（嵌入式 / 芯片 / 测试）。

> 边界处理：JD 写「**不涉及**模型训练」是工程岗正面信号，不能被「模型训练」排除词误杀——筛选器会识别「不涉及 / 无需 / 不要求」等否定词，避免误判。

### 3. 输出

三个文件夹，按匹配度分层：

- `1-高匹配/` — 分数降序，每份 JD 末尾附 5 维评分明细
- `2-候选/` — 未被排除但分数较低
- `3-已排除/` — 附排除原因

## 用 Claude Code 协作的方式

- **痛点先于代码**：先确认「岗位多、筛不过来」是真实问题，再动手
- **AI 辅助设计**：适配器模式、5 维评分模型的结构由 AI 提出，人工确认
- **人工把控关键判断**：反爬方式选型、评分维度定义、以及「不涉及模型训练」这类否定词边界 case——业务判断由人拍板，AI 负责实现

这种「AI 出速度、人出判断」的分工，是这个工具能落地的关键。

## 快速开始

```bash
pip install curl_cffi

# 1. 抓取（字节）
python scraper.py bytedance -k "Agent" -c 后端

# 2. 批量抓取
python scraper.py batch config.json

# 3. 筛选评分
python filter_jds.py -i jd_output -o jd_output_筛选结果
```
